# ledweb

локальная панель управления BLE-лентой на контроллере elk-bledom и его клонах.

демон держит одно ble-соединение постоянно и отдаёт веб-интерфейс на
localhost. почему так: лента отвечает на запись примерно за миллисекунду,
но на connect+disconnect уходит три-четыре секунды. старая схема
«подключился, отправил, отключился» делала каждое действие мучительным.

```
  http://127.0.0.1:8099
```

## что умеет

* постоянное соединение с лентой, очередь команд, автовосстановление
* цвет: hsv-колесо, палитры, hex, температура, свои пресеты
* 11 софтверных эффектов (радуга, дыхание, огонь, северное сияние) —
  считаются на хосте, потому что в прошивке их нет
* встроенные эффекты прошивки, скорость, яркость
* сцены, расписание по дням недели, таймер выключения
* горячие клавиши, тёмная тема, мобильная вёрстка
* rest api + sse, состояние живёт в демоне, вкладку можно закрыть

## запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m ledweb.main --port 8099
```

демон сам поднимет ленту при старте. чтобы он пережил перезагрузку:

```bash
cp ledweb.service ~/.config/systemd/user/
systemctl --user enable --now ledweb
```

## своя лента

mac указывается в настройках либо флагом:

```bash
.venv/bin/python -m ledweb.main --mac AA:BB:CC:DD:EE:FF
```

узнать mac соседних лент:

```bash
bluetoothctl devices | grep -i elk
```

## устройство

| | |
|---|---|
| сервис | `0000fff0-0000-1000-8000-00805f9b34fb` |
| запись | `0000fff3-0000-1000-8000-00805f9b34fb` |
| notify | `0000fff4-0000-1000-8000-00805f9b34fb` (не подписывается) |

кадр — 9 байт:

```
7E LEN CMD P1 P2 P3 P4 P5 EF
```

| команда | код | кадр |
|---|---|---|
| яркость 0-100 | `0x01` | `7e 00 01 VV ff ff ff 00 ef` |
| скорость 0-100 | `0x02` | `7e 00 02 VV ff ff ff 00 ef` |
| вкл | `0x04` | `7e 00 04 f0 00 01 ff 00 ef` |
| выкл | `0x04` | `7e 00 04 00 00 00 ff 00 ef` |
| цвет | `0x05` | `7e 00 05 RR GG BB 00 ef` |
| температура | `0x05` | `7e 00 05 00 00 00 KK ef` |
| эффект | `0x03` | `7e 00 03 00 EE ff ff 00 ef` |
| время | `0x83` | `7e 00 83 00 00 00 00 00 ef` |

`LEN` в разных прошивках бывает `0x00`, `0x04` или `0x07`. по умолчанию
`0x00` — он работает у большинства. если команда не применяется,
переключи вариант протокола в настройках и перезапусти демон.

## важное ограничение

контроллер **не возвращает состояние**. `fff4` не подписывается вовсе,
по `fff3` на чтение отдаётся только модель. поэтому статус в панели —
оптимистичный кэш демона, а не опрос железа. команда, которая не вызвала
ошибку, могла не дойти: единственный честный проверяющий — глаза.

## api

| метод | путь | что делает |
|---|---|---|
| GET | `/api/state` | текущее состояние |
| GET | `/api/meta` | эффекты, палитры, сцены, дни недели |
| POST | `/api/apply` | `{"action":"color","h":270,"s":1,"v":1}` |
| POST | `/api/fx` | софтверный эффект |
| POST | `/api/fx/stop` | остановить эффект |
| GET POST DELETE | `/api/timer` | таймер выключения |
| POST | `/api/scene` | сцена по id |
| GET POST PATCH DELETE | `/api/presets` | свои пресеты |
| GET POST DELETE | `/api/rules` | расписание |
| GET | `/api/scan` | поиск лент рядом |
| GET | `/api/stream` | sse с состоянием |
| GET | `/api/health` | живость |

## структура

```
ledweb/
├── protocol.py   байт-коды, палитры, сцены
├── driver.py     соединение, очередь, кэш состояния, реконнект
├── fx.py         софтверные эффекты
├── store.py      пресеты, правила, настройки
├── server.py     http + sse + api, только стандартная библиотете
├── main.py       точка входа
└── static/       index.html, app.css, app.js, токены, шрифты, lucide
```

веб без сборщика и без зависимостей. сервер тоже на стандартной библиотеке:
flask и fastapi тут не дают ничего, кроме лишних миллисекунд на старте.
